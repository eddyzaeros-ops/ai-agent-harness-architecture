演進史：走向駕馭工程

第一階段：提示詞工程 (Prompt Engineering)

2023 - 2024

核心在於如何「問對問題」。透過 Few-shot、Chain of Thought (CoT) 引導模型生成。系統是被動的問答機器。

第二階段：上下文工程 (Context Engineering)

2024 - 2025

核心轉向 RAG 與記憶管理。著重於如何有效地檢索、過濾和注入相關背景資訊。系統開始具備有限的長期記憶。

第三階段：駕馭工程 (Harness Engineering)

2026 - 至今

核心在於構建「執行環境」。模型成為 CPU，Harness 則是作業系統，提供工具、監控、沙盒與多步驟自主規劃能力。

六層架構模型 (6-Layer Harness)

1. 使用者介面層 (UI/UX)
2. 編排層 (Orchestration)
3. 智能層 (Intelligence)
4. 能力層 (Capability)
5. 安全治理層 (Security)
6. 基礎設施層 (Infrastructure)

1. 使用者介面層 (UI)

負責與開發者/使用者的終端交互，不僅僅是命令列列印，而是富文本、動態進度與中斷介入的綜合體驗。

關鍵組件

  • CLI 渲染引擎 (基於 React/Ink)
  • Markdown/Diff 高亮顯示器
  • 動態微調工具 (Spinners, 進度條)
  • 中斷與人工介入 (Human-in-the-loop) 提示

2026源碼洞察

現代 CLI Harness 摒棄了單純的 print()，採用聲明式 UI 框架。例如 Claude Code 的 TUI 使用了 React 渲染到終端，實現複雜的並發任務狀態樹展示。

2. 編排層 (Orchestration)

Agent 的「中央處理器」，負責任務生命週期、狀態機轉移、錯誤恢復與子 Agent 派發。

核心機制

  • Agentic Loop (任務回環引擎)
  • Hook System (生命週期鉤子)
  • 狀態快照與回滾機制
  • 並發子任務協調器

2026源碼洞察

核心回環代碼通常少於 100 行。如 loop { prompt; call_llm; parse_action; execute; observe; if_done_break; }。複雜性在於錯誤處理與 Token 截斷重試邏輯。

3. 智能層 (Intelligence)

管理與底層大模型的通訊、提示詞組裝、上下文視窗維護及成本控制。

關鍵技術

  • 動態 Prompt 組裝 (6層疊加)
  • KV Cache 管理與路由
  • 資訊熵壓縮 (防止上下文溢出)
  • 結構化輸出解析 (JSON/XML)

上下文治理 (2026)

採用「三級記憶機制」：工作記憶 (當前輪次)、情節記憶 (近期日誌摘要) 與語義記憶 (向量庫)。當 Token 達到 83.5% 閾值時自動觸發無損壓縮。

4. 能力層 (Capability)

Agent 與物理世界/數字世界互動的手腳，即 Tool/Function Calling 介面與實作。

標準工具集 (19+)

  • 檔案操作 (讀/寫/修補 Patch)
  • Bash/PowerShell 執行器
  • AST 解析與語義搜尋 (Grep/AST)
  • 網頁瀏覽與 DOM 交互

MCP 協定

2026年，模型上下文協議 (MCP) 成為標準。工具不再寫死在代碼中，而是透過 MCP Server 動態發現與加載 (Lazy loading)。

5. 安全治理層 (Security)

防止 Agent 暴走、刪除關鍵檔案或執行惡意代碼的護城河。

三級風控

  • L1: 靜態命令攔截 (如 rm -rf)
  • L2: 執行前人工確認 (sudo/部署)
  • L3: 沙盒隔離 (Docker/gVisor)
  • 預算上限 (Budget Cap)

安全哲學

Zero-trust 架構。所有 Agent 發起的外部請求均需攜帶追蹤 ID。關鍵破壞性操作強制進入 approval_loop 阻塞等待授權。

6. 基礎設施層 (Infrastructure)

支撐整個框架運行的底層服務，如守護行程、遙測日誌、配置管理與網路隧道。

底層服務

  • 背景 Daemon 服務 (如 KAIROS)
  • Telemetry (遙測資料收集)
  • 身分驗證與 Token 管理
  • 持久化鍵值存儲 (Local SQLite)

Daemon 架構

為了支援離線任務與長時運行，UI (Layer 1) 與執行體 (Layer 6) 完全解耦。終端關閉後，Daemon 仍在背景執行並保存狀態。

Big Model vs Big Harness

業界出現分歧：一派主張提升模型原生 Reasoning 能力 (如 OpenAI o1)，減少外部腳手架；另一派主張模型作為純邏輯核心，投入巨資打造「大駕馭」框架 (Big Harness) 以適應現實複雜環境。

🐝

Agent Swarm 群智方向

多智能體協作演化出四種生產模式：

  • > 分層管理 (Hierarchical)
  • > 聯合辯論 (Debate)
  • > 流水線作業 (Pipeline)
  • > 異構路由 (Router-Worker)
📉

腳手架變薄 — 逆向增長

隨著基座模型 Context 擴展至百萬級，RAG 的價值被稀釋。未來的 Harness 將把重心從「記憶管理」轉移到「環境互動」與「高階安全校準」上，代碼量可能先增後減。
